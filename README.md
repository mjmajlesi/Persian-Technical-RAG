# Persian Technical RAG

**پرسش‌وپاسخ فارسی دربارهٔ C، C++، Python و Java، با بازیابی از منابع مشخص و ارجاع قابل‌بررسی.** این پروژه نمونهٔ پایان‌نامهٔ کارشناسی است، نه یک دستیار همه‌چیزدان: اگر منابعِ زبان انتخاب‌شده برای پاسخ کافی نباشند، سیستم باید به‌جای ساختن جواب یا ارجاع، انصراف دهد.

هر زبان یک **LanguagePack** مستقل دارد: منابع فریز‌شده، ایندکس FAISS جداگانه، آستانهٔ انصراف کالیبره‌شده و مجموعهٔ ارزیابی نسخه‌دار. داشبورد راست‌به‌چپ، C را پیش‌فرض انتخاب می‌کند و با تغییر زبان، محدودهٔ بازیابی و نمای پرسش را عوض می‌کند.

## سازوکار در یک نگاه

```text
سؤال فارسی + زبان انتخاب‌شده
    → بازیابی از ایندکس همان زبان (multilingual-e5-large + FAISS)
    → بررسی آستانهٔ شباهت همان پک
    → ساخت پاسخ فارسی فقط از چانک‌های بازیابی‌شده با LLM
    → بررسی ارجاع‌ها در ایندکس پک انتخاب‌شده
    → پاسخ مستند / انصراف / درخواست توضیح
```

منابع زبان دیگر برای پاسخ یا ارجاع باز نمی‌شوند. سؤال کوتاه و مبهم درخواست توضیح می‌گیرد؛ پک بدون ایندکس نیز وضعیت `unavailable` دارد. پرسش‌های خارج از پیکره پیش از تماس با مدل یا، در موارد مرزی، پس از تشخیص ناکافی‌بودن زمینه توسط مدل به انصراف می‌رسند.

## پک‌ها و نتایج ثبت‌شده

| زبان | ترکیب منابع | چانک | Hit@5 | دقت ارجاع | انصراف خارج‌پیکره | آلودگی بین‌پکی | گزارش |
|---|---|---:|---:|---:|---:|---:|---|
| C | جزوهٔ فارسی + مراجع انگلیسی C | 503 | 1.000 | 0.657 | 5/5 | 3/3 | [گزارش C](data/eval/c/reports/2026-10-22-0748-c-v1.md) |
| C++ | جزوهٔ فارسی + cppreference | 201 | 0.600 | 0.812 | 5/5 | 3/3 | [گزارش C++](data/eval/cpp/reports/2026-10-22-0753-cpp-v1.md) |
| Python | مستندات انگلیسی رسمی | 253 | 0.760 | 0.602 | 5/5 | 3/3 | [گزارش Python](data/eval/python/reports/2026-10-22-0758-python-v1.md) |
| Java | مستندات انگلیسی رسمی | 73 | 0.920 | 0.706 | 5/5 | 3/3 | [گزارش Java](data/eval/java/reports/2026-10-22-0802-java-v1.md) |

این اعداد از اجرای انتهابه‌انتهای **۲۰۲۶-۱۰-۲۲** پس از بازسازی هر چهار ایندکس‌اند؛ همهٔ گزارش‌های جدول بدون خطای مدل‌اند. برای هر پک، ۲۰ سؤال درون‌پیکره + ۵ سؤال mixed + ۵ سؤال خارج‌پیکره و **۳ probe مستقلِ آلودگی** اجرا شده است. Hit@5 سهم سؤال‌های پاسخ‌دادنی با منبع موردانتظار در پنج بازیابی اول است؛ دقت ارجاع سهم ارجاع‌های پاسخ‌های تولیدشده است که به چانک واقعیِ موردانتظار اشاره می‌کنند. نتیجهٔ ۳/۳ آلودگی فقط به همین probeها مربوط است و به‌تنهایی اثبات عملکرد روی همهٔ پرسش‌های بین‌زبانی نیست. خروجی LLM می‌تواند میان اجراها تغییر کند؛ نتیجهٔ تازه را فقط وقتی نقل کنید که گزارش `Status: complete` و `error_count=0` داشته باشد.

Python و Java عمداً فقط مراجع انگلیسی دارند؛ این محدودیت در تفسیر کیفیت پاسخ فارسی مهم است. [مقایسهٔ مهاجرت C با نسخهٔ تک‌زبانهٔ 001](docs/MIGRATION-RESULTS.md) نیز جداگانه ثبت شده است.

## راه‌اندازی محلی

دستورهای زیر برای **Python 3.11 و PowerShell**، از ریشهٔ مخزن هستند. وابستگی‌های مستقیم در `requirements.txt` پین شده‌اند. دریافت اولیهٔ مدل embedding ممکن است به اینترنت و فضای دیسک نیاز داشته باشد؛ تولید پاسخ نیز به سرویس LLM نیاز دارد.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

در فایل محلی `.env`، سه مقدار `LLM_API_KEY`، `LLM_BASE_URL` و `LLM_MODEL` را برای یک API سازگار با OpenAI تنظیم کنید؛ **کلید واقعی را در مخزن ثبت نکنید**. provider هم پاسخ JSON معمولی و هم پاسخ جریانی SSE را می‌پذیرد. بدون LLM فعال، ingest و ساخت ایندکس ممکن است، اما پاسخ‌سازی و ارزیابی کامل نه.

ایندکس‌های حجیمِ ساخته‌شده در git نگهداری نمی‌شوند؛ پیش از اجرای داشبورد، آن‌ها را از منابع فریز بسازید:

```powershell
foreach ($lang in 'c', 'cpp', 'python', 'java') {
    .\.venv\Scripts\python -m src.ingest --lang $lang
    .\.venv\Scripts\python -m src.index build --lang $lang
}
```

خروجی موردانتظار به‌ترتیب 503، 201، 253 و 73 چانک است. هر دستور فقط در `data/index/<lang>/` همان زبان می‌نویسد؛ منشأ، تاریخ snapshot و مجوز هر منبع در `data/corpus/manifest.<lang>.json` ثبت شده‌اند. مسیرهای قدیمیِ تک‌زبانه دیگر مسیر اصلی پروژه نیستند و نیازی به اجرای دوبارهٔ مهاجرت ندارید.

## اجرا و یک پرسش نمونه

```powershell
.\.venv\Scripts\python -m uvicorn src.web.app:app --port 8000
```

داشبورد را در **http://localhost:8000** باز کنید. از نوار کناری زبان را انتخاب کنید و مثلاً برای C بپرسید: «تفاوت malloc و calloc چیست؟». ارجاع‌های پاسخ با کلیک، منبع و چانک را نشان می‌دهند. API نیز در `/docs` مستند شده است:

```powershell
$body = @{ language = 'c'; question = 'تفاوت malloc و calloc چیست؟' } | ConvertTo-Json
Invoke-RestMethod -Uri 'http://localhost:8000/api/ask' `
    -Method Post -ContentType 'application/json; charset=utf-8' -Body $body
```

`GET /api/languages` پک‌ها و وضعیتشان را برمی‌گرداند؛ `POST /api/ask` بدون `language` از C استفاده می‌کند. شناسهٔ زبان ناشناخته خطای 422 می‌دهد. پاسخ‌ها بسته به سؤال `answer`، `abstain`، `clarify` یا `unavailable` هستند.

## آزمون و ارزیابیِ قابل‌بازتولید

```powershell
.\.venv\Scripts\python -m pytest tests/ -q
foreach ($lang in 'c', 'cpp', 'python', 'java') {
    .\.venv\Scripts\python -m src.eval run --lang $lang
}
```

در آخرین اعتبارسنجی ثبت‌شده، **۳۲ تست پاس** شدند. هر اجرای ارزیابی گزارش Markdown و JSON مخصوص همان زبان را در `data/eval/<lang>/reports/` می‌نویسد؛ JSON محلی در git نادیده گرفته می‌شود. مجموعهٔ probeهای بین‌پکی در `data/eval/contamination.v1.json` نسخه‌بندی شده است. **امتیاز کلیِ ادغام‌شده برای چهار زبان گزارش نمی‌شود.** اگر سرویس مدل خطا یا محدودیت نرخ بدهد، گزارش ناقص علامت می‌خورد و دستور با کد ناموفق پایان می‌یابد؛ چنین گزارشی را مبنای مقایسه قرار ندهید.

## مسیرهای مهم و دامنهٔ پروژه

- `src/ingest/` و `src/index/`: تبدیل منابع فریز به چانک و ایندکس مستقل هر پک؛ `src/qa/`: بازیابی، تولید پاسخ، اعتبارسنجی ارجاع و انصراف.
- `src/web/`: API و داشبورد؛ `src/eval/`: کالیبراسیون و امتیازدهی؛ `tests/`: آزمون‌های واحد، قراردادی و یکپارچه‌سازی.
- [`راهنمای مرحله‌به‌مرحلهٔ بازتولید`](specs/002-multi-language-dashboard/quickstart.md) · [`مشخصات ویژگی چندزبانه`](specs/002-multi-language-dashboard/spec.md) · [`اصول پروژه`](.specify/memory/constitution.md).

این پروژه یک نمونهٔ **محلی و تک‌کاربره** با چهار پیکرهٔ محدود و فریز‌شده است؛ احراز هویت، مقیاس‌پذیری تولیدی، خزیدن زندهٔ وب و پاسخ‌گویی خارج از منابعِ پک انتخابی در دامنهٔ آن نیستند.
